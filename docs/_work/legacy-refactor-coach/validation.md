# 五场景规则演练与验证记录

日期为 2026-11-10。以下为创建者依据最终入口、workflow、templates、migration 与 verification 执行的模拟输入/流程推演，未启动独立 Agent，未在真实历史工程实施迁移。

| 模拟输入与前提 | 本轮按 Skill 选择的行动与检查 | 演练结果 |
| --- | --- | --- |
| 无文档 Spring Boot + Vue，用户说“开始重构” | 默认指导，进入 P0，读取 Git/构建与锁文件识别版本及运行限制；按项目规则发现或建立最小资料路由；未知数据库版本标尚未核实；不改业务代码 | 能路由到 P0 与 discovery，缺文档不会被当作已完成审计 |
| 新工程仅保留 30% 核心功能，其他去留未确认 | P0 核对旧/新路径；P1 追踪保留能力与数据依赖；P2 逐项处置，用户未决定的其余能力仍待决策；P3 比较目标边界，禁止复制旧目录或自动删剩余功能 | 允许部分保留和新建，核心取舍待用户决定 |
| 在线运行系统，只能逐步替换，订单写入有外部发信副作用 | 按 P5/P6 单元迁移；明确写入与任务所有者，Expand-Migrate-Contract，查询影子验证评估负载；禁止双写/双发信盲目对比；生产切流核实授权与回滚证据 | 连续运行约束进入迁移计划，未获切流授权不能自行生产切换 |
| 已迁移模块，状态记录 Gate 已通过，但新会话 Git HEAD 与 API 有变化 | 先恢复读取状态和证据；对比分支/HEAD/dirty diff/API；受影响 Gate 退回复核，下游标待复核；不重新询问仍有效的批准；只继续当前范围下一项安全任务 | 旧状态不能覆盖真实源码变化，恢复可定位验证失效范围 |
| 用户说“跳过分析，直接改支付功能” | 执行请求明确，但需定位入口/调用链/数据，建立该功能所需最小 P0–P4 与特征测试；不强制全仓审计；未满足当前门禁保持执行中/等待决策，禁止盲改关键权限或已确认行为 | 小范围实施诉求可推进，核心行为和数据保护门禁仍有效 |
