# Prototype Greenfield

## 目标

从空目录或无可复用前端工程的情况下，创建一套可运行、可点击、可用于评审的高保真原型。

## 前置条件

至少基本明确：产品目标、角色、核心场景、页面清单、关键字段/状态/操作和范围。核心业务规则不清时应先回到需求/方案阶段。

## 技术选择

- 单页简单演示：单文件 HTML。
- 多页面轻量原型：HTML + CSS + JavaScript。
- 页面多、组件复用明显、状态复杂：React 或 Vue。

原则：能用简单方式可靠完成，就不要引入更重框架。

## 核心规则

1. 先拆页面架构、导航、流程、字段、状态和交互，再写代码。
2. 建立统一设计变量和组件规则。
3. 至少一条核心业务流程必须可完整点击。
4. 模拟数据使用真实业务语义，覆盖正常、异常、空、禁用和边界状态。
5. 不擅自新增核心业务模块、状态、权限或审批规则。
6. 后台/行业系统默认强调信息密度和可读性，不做营销官网式 Hero、光效和过度渐变。
7. 生成后必须本地运行并检查关键页面和交互。

## 编码前输出

- 产品目标与角色
- 页面树/导航结构
- 页面跳转关系
- 关键字段/状态/权限
- 必须实现的交互
- 技术方案及理由
- 必要假设

## 最低交互覆盖

按需求选择实现：搜索、筛选、Tab、详情、弹窗/抽屉、表单、校验、新增/编辑、状态切换、确认、成功/失败反馈、空状态、禁用状态。

## 验收

- 项目可启动。
- 无明显构建/运行错误。
- 页面入口可达。
- 核心流程可走通。
- 模拟数据和状态符合需求材料。
- 不存在明显样式断裂或不可读区域。

## 输出

- 项目文件和启动方式。
- 页面/交互完成清单。
- 使用的模拟数据说明。
- 未实现项和必要假设。
- 本地验证结果。
