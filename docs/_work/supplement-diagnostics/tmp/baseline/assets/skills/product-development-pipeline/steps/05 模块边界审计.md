# Step 05：模块边界 Gate ②-A

## 目标

在模块结构冻结前，检查职责是否稳定、是否存在重叠、伪模块和高扩散耦合风险。

本步骤只审计 Step 04 的模块方案，不负责重新设计整套架构。

## 输入

- 推荐方案。
- 模块/能力树。
- 模块职责。
- 核心对象和主流程。

## 检查项

1. **职责单一性**：模块是否是稳定责任容器，而不是零散功能堆。
2. **职责重叠**：两个模块是否都拥有同一业务事实、状态或决策权。
3. **边界语义**：模块名称和职责能否明确判断一项能力该归哪里。
4. **变化源**：变化原因不同的能力是否被错误绑在一起。
5. **跨域耦合**：一个模块是否同时依赖多个业务域并承担协调职责。
6. **伪模块**：是否因为页面、菜单、技术层或当前实现方便而创建业务模块。
7. **未来扩散**：典型需求变化是否会迫使多个模块同步修改。

## 每个问题必须说明

- 涉及模块。
- 当前边界。
- 冲突类型。
- 一个真实可能发生的变化场景。
- 继续推进会返工哪里。
- 建议动作：Accept temporarily / Clarify before freeze / Block freeze。

## Gate 结论

- `PASS`：模块职责和边界足以冻结。
- `CONDITIONAL PASS`：存在可接受风险，有明确限制和关闭条件。
- `FAIL`：存在职责重叠、核心边界不清或变化会大面积扩散的问题。

## 输出

- Gate 状态。
- 主要模块问题清单。
- 可接受结构风险。
- 冻结前必须确认事项。
- 失败时回退 Step 04。
