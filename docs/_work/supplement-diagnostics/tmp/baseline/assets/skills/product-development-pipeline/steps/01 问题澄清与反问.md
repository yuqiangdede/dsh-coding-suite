# Step 01：需求澄清与问题边界冻结

## 定位

本阶段直接遵循 `requirement-clarification` 能力，不在流水线内部维护第二套澄清方法论。

## 目标

把模糊需求整理成足以进入需求分析的已确认输入，并冻结“这次到底要解决什么”。

## 执行要求

1. 先读取用户已经提供的全部信息，禁止重复询问。
2. 只识别会改变需求方向的关键缺口。
3. 每轮最多提出 1–3 个高价值问题。
4. 优先级：核心问题 → 用户/角色 → 场景 → 当前流程 → 期望结果 → 范围/限制 → 验证标准。
5. 用户提出的功能方案只标记为“已有方案”，不能自动等同于真实问题。
6. 所有推测必须标记为待确认/待验证。

## 完成条件

以下内容已基本明确且无方向性冲突：

- 背景。
- 目标用户/角色。
- 核心场景。
- 当前问题。
- 期望结果。
- 本期范围与主要限制。

## 输出契约

- 已确认事实
- 业务判断
- 已有方案
- 待验证假设
- 核心问题
- 目标用户/角色
- 关键场景
- 当前流程概述
- 期望结果
- 本期范围/非目标
- 限制与依赖
- 待确认但不阻塞项

结论：`READY_FOR_ANALYSIS` 或 `NEED_MORE_CLARIFICATION`。

只有 `READY_FOR_ANALYSIS` 才进入 Step 02。
