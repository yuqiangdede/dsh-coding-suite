# Step 10：输出路由

## 定位

Gate ③ 通过后，根据用户真实目标选择交付方式。DSH「需求全流程」默认选择路由 B，完成从澄清到 UI 生图提示词的交付；用户明确只要文档或原型时选择其指定路由。生成提示词不授权实际生图。

## 前置条件

Step 09 必须为 `PASS`，或 `CONDITIONAL PASS` 的关闭条件已经满足。

## 路由 A：仅交付设计文档

适用于用户只需要需求/方案/PRD/页面规格用于评审或交接。

输出：

- 最终确认范围。
- 方案与核心设计。
- PRD。
- 页面规格。
- Gate 结果和遗留项。

不生成代码或 UI Prompt。

## 路由 B：UI Prompt / 效果图规格

适用于用户希望生成静态 UI 效果图。

规则：

- 一次处理一个指定页面。
- 只把 Step 08 页面规格转成结构说明和文生图 Prompt。
- 不重新增加业务字段、按钮、模块、状态或权限。
- 视觉风格缺失时可以给建议；业务内容缺失必须回退确认。
- UI 字段标签和模拟数据遵守 Step 08 的语言配置。

交付时保留 PageId、稿件版本、角色/任务、布局、字段/示例数据、操作前置及结果状态、权限、正常/空/加载/错误/禁用状态、视觉和语言约束；给出可复制的提示词与必要限制。实际生图仅在用户明确请求时调用，不因具备生图能力自动继续。

## 路由 C：从零可运行原型

适用于没有现成前端项目，需要真正可点击演示。

调用 `prototype-greenfield`，输入：

- 已评审 PRD。
- 页面规格。
- 核心流程/状态/权限。
- 全局展示配置。

输出 HTML/CSS/JS、React 或 Vue 原型，并完成本地运行检查。

## 路由 D：已有项目原型

适用于用户已经提供现有前端工程。

调用 `prototype-existing-project`。

必须先扫描当前项目技术栈、路由、组件、Design Token 和相似页面，再做最小范围修改；禁止把 Greenfield 方案硬塞进已有项目。

## 路由选择规则

- 用户明确指定输出时，直接遵循。
- 用户说“做效果图/生图提示词” → B。
- 用户说“做可以点击/运行的 Demo”，且无现成项目 → C。
- 用户说“在这个项目里加页面/原型” → D。
- 用户明确只要设计文档 → A；使用 DSH「需求全流程」且未另选终点 → B，产出提示词后停止，不继续生图或实现。

## 最终输出

- 选择的路由。
- 使用的已确认上游输入。
- 实际交付物。
- 未关闭事项和假设（如有）。
- 若生成原型，附运行/验证结果。
