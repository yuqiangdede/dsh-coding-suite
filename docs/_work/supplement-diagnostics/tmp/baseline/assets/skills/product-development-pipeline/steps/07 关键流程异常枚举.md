# Step 07：关键流程异常补全 Gate ②-B2

## 目标

在主流程和状态模型已稳定的前提下，系统枚举关键失败路径，确保异常发生后系统有明确归宿，并能被状态、权限和页面承载。

本步骤不优化主流程，不重新设计模块。

## 输入

- 范围内核心端到端流程。
- 核心对象和状态流转。
- 角色/权限框架。
- Step 06 Gate 结果。

## 每条流程至少扫描

1. 输入异常：缺失、非法、冲突、重复提交。
2. 状态异常：非法跳转、并发修改、对象已失效。
3. 权限异常：越权、角色变化、负责人变化。
4. 时间异常：超时、过期、跨周期、延迟。
5. 外部依赖异常：接口失败、第三方不可用、审批人/设备/资源缺失。
6. 执行结果异常：部分成功、重复执行、幂等冲突、结果未知。
7. 人工介入：撤回、驳回、取消、重新指派、人工兜底。

## 异常必须有归宿

只能落到明确系统行为，例如：

- 回滚。
- 中断并留痕。
- 进入异常状态等待处理。
- 重试/补偿。
- 转人工队列。
- 明确终止。

“提示用户”“人工处理”本身不是完整异常设计，必须说明之后对象处于什么状态、谁能继续做什么。

## 每个异常输出

- 所属流程。
- 触发条件。
- 涉及角色。
- 前置状态 → 结果状态。
- 系统行为。
- 是否需要页面入口。
- 谁拥有后续操作权限。
- 严重程度。

## Gate 结论

- `PASS`：关键异常有明确归宿且状态模型可承载。
- `CONDITIONAL PASS`：只剩低概率/非核心异常，已记录关闭条件。
- `FAIL`：存在高风险异常无归宿、状态无法表达、无人有权继续处理等情况。

## 输出

- Gate 状态。
- 逐流程异常清单。
- 跨流程共性异常。
- 必须补充的状态/权限/页面能力。
- 失败时回退 Step 04/06。

通过后才进入 Step 08 PRD 与页面规格。
