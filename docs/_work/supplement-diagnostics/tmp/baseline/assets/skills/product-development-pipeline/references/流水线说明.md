# Legacy：LLM 软件设计流水线（历史 01–10 版本）

> **状态：历史参考，不作为当前执行规范。**
>
> 当前唯一执行入口是 `../SKILL.md`（`product-development-pipeline`）。当前版本已经引入 `product-development-skills` 能力库、PRD 独立评审和多路输出；本文件仅保留早期设计思想和 Gate 演进记录。

## 历史定位

早期版本面向 B 端 / 行业系统，把模糊业务想法按固定顺序推进到模块、数据、流程、页面规格和 UI Prompt。

历史流程如下：

```text
01 问题澄清与反问
02 问题拆解
03 需求风险扫描        ← Gate ①
04 决策与方案对比
05 模块边界与职责冲突审计
06 数据模型与状态完整性校验  ← Gate ②
07 关键流程异常枚举
08 需求分析与页面规格生成
09 页面-流程-权限一致性校验  ← Gate ③
10 UI Prompt 渲染
```

## 当前版本与历史版本的主要差异

当前 `product-development-pipeline` 已调整为：

- 需求澄清、需求分析、方案设计、PRD、评审和原型能力拆入 `product-development-skills`。
- Step 08 改为 `PRD → 独立评审 → 页面规格`，不再重新跑需求到模块的子流程。
- Gate 状态统一为 `PASS / CONDITIONAL PASS / FAIL`。
- Step 10 改为输出路由，可选择文档、UI Prompt、Greenfield 原型或 Existing Project 原型。
- 模块、数据/状态、异常、页面/流程/权限 Gate 继续保留。

## 历史 Gate 思想

### Gate ①：需求风险

用于拦截目标不清、边界失控、隐含假设过多的需求。

### Gate ②：模块、数据与状态

用于拦截职责冲突、状态过载、状态不可回收以及隐式状态依赖。

### Gate ③：页面、流程与权限一致性

用于拦截流程无页面入口、页面操作无权限主体、异常流程无 UI 承载等问题。
