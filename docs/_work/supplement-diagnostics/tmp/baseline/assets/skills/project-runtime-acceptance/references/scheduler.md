# JOB：全局定时任务、冲突与执行可靠性

## 任务发现

源码/配置/运维平台统一汇总：Spring `@Scheduled`、Quartz、XXL-JOB、ElasticJob、Celery Beat/APScheduler、Cron/systemd timer、Kubernetes CronJob、云平台调度器、Redis 延时队列、业务自行 while-loop 定时器、前端轮询（跨 API 域审查）。运行中注册的任务与代码比对。

每任务记录：稳定 ID、服务/实例范围、Cron/间隔/时区、触发开关、平均与 P99 耗时、并行策略、执行资源与表、读写意图、锁机制、幂等键、重试上限、错误路径、上下游任务依赖、任务运行证据。

## 规则

| ID | 检查点 | 判定依据 |
| --- | --- | --- |
| JOB-001 | 多实例任务重复触发 | 各节点执行 + 缺乏单实例调度/分布式协调 + 操作非幂等 |
| JOB-002 | 前一轮与下一轮重叠 | 实际最大耗时超过调度间隔，且框架允许并发或锁失效 |
| JOB-003 | 不同任务写同一资源冲突 | 交叉表/对象/文件键 + 写入顺序、隔离与锁分析 |
| JOB-004 | 归档、清理顺序错误 | 清理必须等待归档成功，失败/延迟时不能破坏源数据 |
| JOB-005 | 锁生命周期错误 | 锁超时早于实际工作、续租失败、租约漂移、误释放 |
| JOB-006 | 不幂等 | 同一批次/消息二次执行导致重复新增/扣减/推送/删除 |
| JOB-007 | 重试风暴 | 内部重试叠加调度重试、缺上限/退避/去重 |
| JOB-008 | 异常无感知 | 异常吞掉、失败记成功、无通知/重跑能力 |
| JOB-009 | 资源峰值冲突 | CPU、磁盘 IO、数据库锁、连接数负载叠加有实际容量风险 |
| JOB-010 | 时区/DST/Cron 解释差异 | Spring/Quartz/Cron 表达式差异，错过/多触发计划 |
| JOB-011 | 滞留状态无法回收 | 任务卡死、取消/重启后无法恢复状态 |
| JOB-012 | 执行计划不可见 | 任务注册清单与生产实际开关/错峰配置不一致 |

## 冲突判定矩阵

1. 时间是否可能重叠？静态 Cron 推断只证明**可能**。
2. 是否同时读取/修改相同对象？纯读取通常不是业务冲突，但会形成资源峰值。
3. 是否有共享锁、乐观并发控制、幂等约束或任务顺序控制？
4. 冲突后是否可恢复？有监控、告警和补偿吗？

报告用 `任务A ↔ 任务B | 交集资源 | 交叠窗口 | 冲突条件 | 协调机制 | 证据状态` 展示，不得把“同一时刻”直接定为 P0。

## 运行时验证（授权后）

任务执行历史、每实例日志、最大/分位耗时、重入次数、租约状态、失败与重试记录；只读观察，不主动触发任务。对多实例时钟偏差、主备切换、进程重启特别关注。
