# Prototype Existing Project

## 目标

让新增原型看起来是现有产品自然扩展出来的，而不是在同一仓库里重新做一套系统。

## 强制第一步：扫描现有项目

开始写代码前确认：

- 框架与构建工具。
- 路由和页面组织方式。
- UI 组件库和图标库。
- 样式方案、主题、CSS 变量/Design Token。
- 现有布局、表格、表单、弹窗、抽屉、消息组件。
- 状态管理和模拟/请求方式。
- 相邻或同类型页面。
- 启动、构建和测试命令。

## 核心规则

1. 优先复用，不建立第二套组件体系。
2. 新页面遵守现有信息密度、间距、字体、颜色和导航结构。
3. 原型目标优先，不为了 Demo 引入大规模架构重构、重型依赖或复杂状态机。
4. 默认使用页面级或功能级模拟数据，不主动接生产接口。
5. 已有业务事实不得被视觉优化改变。
6. 缺少展示细节可合理补充；会改变业务范围/状态/权限的内容必须标记待确认。
7. 修改后必须运行现有项目并检查受影响页面。

## 实现流程

1. 识别技术栈。
2. 寻找最相似页面和组件。
3. 列出应复用内容。
4. 确定新增/修改页面和路由入口。
5. 定义模拟数据和交互状态。
6. 最小范围实现。
7. 运行/构建检查。
8. 检查是否破坏原页面或全局样式。

## 最低交互覆盖

按需求实现搜索、筛选、列表/详情、Tab、弹窗/抽屉、表单、校验、状态变化、确认、空/加载/错误/禁用状态以及完整返回路径。

## 禁止事项

- 为新页面复制一套已有组件。
- 无必要更换 UI 框架。
- 无必要全局改主题。
- 为原型先设计后端服务层。
- 未检查现有代码就直接生成页面。

## 输出

- 修改/新增文件清单。
- 复用的现有组件和约定。
- 可点击流程说明。
- 必要假设和未实现项。
- 启动/构建验证结果。
