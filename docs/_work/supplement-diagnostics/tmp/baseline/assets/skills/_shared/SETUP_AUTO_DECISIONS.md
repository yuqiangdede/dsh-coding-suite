# 初始化：推荐项自动处理，例外才询问

本规程适用于 `/setup-matt-pocock-skills` 的目标项目。用户授权**可验证且非破坏性**的工程初始化推荐项自动采用并执行，不重复询问“是否采用推荐项”。它不授权修改业务事实、安装软件或操作远端。

## AUTO — 直接实施并记账

须同时满足：真实文件/目录、现行文档权威、项目根路径唯一可验证；修改只涉及工程初始化元文件、路径指针、错字；不覆盖已有用户变更、不删除/搬迁既有正式资料、不改变业务语义。

- 复用现有 `CLAUDE.md` 或 `AGENTS.md`；两者都不存在时默认建立 `AGENTS.md`。选择已有索引和真实权威目录；没有有效索引则新建最小 Pocket 索引。补齐 `docs/agents/issue-tracker.md`、`domain.md`、`document-layout.md`、登记的工作目录及 README；缺少的分类目录按需建立，不预建空目录。
- 明确的 GitHub/GitLab remote 可以默认对应的本地 Issue Tracker 配置；没有远端则推荐本地 Markdown 记录。只有本地配置自动写入；**不自动创建远端标签/Issue 或安装 CLI**。没有 triage Skill 则跳过标签；有 Skill 且未配置标签且无冲突时采用五个默认值。
- Skill 默认目录（如 `docs/Requirements/`、`docs/Design/`、`docs/pocket/handover/`）只是提示。与已验证项目布局不一致时自动服从现行权威，**不生成第二套目录**；交接资料使用布局登记的“验收与交接”回退目录。
- 仅有一种现行大小写拼写时采用磁盘实际名称。例如确实存在 `docs/Integration/`，而该目录 README 自述 `docs/integration/` 时，**只修复该 README 的唯一匹配文本**；不创建小写目录，不改变业务文档。可用 `scripts/auto_reconcile.py <project-root> --apply-safe`，脚本会跳过 Git 未提交修改、冲突和不确定情况。
- 补齐不冲突的 Agent 根指针、初始化目录说明、索引引用等结构性元数据。先读取最新内容并验证唯一修改点，逐文件记录“推荐→依据→结果”。

## NEEDS_DECISION — 只针对例外征求一次确认

两份不同的有效文档都可能是权威；磁盘上大小写目录同时存在；索引与文件不一致、源文件有未提交修改、路径超出项目、符号链接越界；需要覆盖/迁移/删除/合并已有资料，或修改业务规则、正式规范、生产配置；需要安装 Skill/依赖、联网、修改远端 Issue 或推送提交。这些项目**暂停对应写入**，集中列出唯一推荐方案、影响及待确认问题；无关 AUTO 项继续执行。

## 执行原则

先盘点→分级→直接实施 AUTO→重读文件与目录验证→汇总已修复、跳过项、真正待决策项。失败或跳过不等于成功；不能以按钮被点击或用户未回复代表初始化通过。此授权仅针对安全工程初始化，不改变其他 Skill 的业务文件差异预览和审批要求。
