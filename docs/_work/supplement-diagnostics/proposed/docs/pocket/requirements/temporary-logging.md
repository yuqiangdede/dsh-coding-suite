## 交互与范围

- 按钮显示“补充排查”，常用组和开发组共享同一入口。内部沿用 add-logs ID，保持既有布局成员与位置。
- 点击展开四个选项：功能排查-页面模式、功能排查-日志模式、性能排查-页面模式、性能排查-日志模式；依次调用 diagnose-function-page、diagnose-function-logs、diagnose-performance-page、diagnose-performance-logs。
- 选模式后检查 Skill 可用性并插入可编辑草稿，由用户发送；取消不插入，不自动执行。沿用初始化检查、输入位置保护及通用禁用条件。
- 默认针对本对话已完成编码的功能；未完成或目标含糊由 Skill 核实并询问。按钮不以关键词推断编码已完成，不声称自动判定执行结果。
- 可识别且提示词完全未改的旧“增加日志”预设自动升级，保留启用/固定/顺序与自定义说明；自定义名称或提示词保留原状，不新增用户删除的动作。

## 四种模式

- 功能页面：结论、执行步骤、展开详情、基于证据的建议，区分接口技术成功、无数据/回退和最终业务结果；缺反馈标未验证。
- 功能日志：按 runId 关联关键步骤、脱敏输入输出摘要、分支/回退和最终结论，不新增页面。
- 性能页面：共享采集及组件，显示可靠总耗时、步骤耗时、耗时条、排序、最慢步骤和可比占比。
- 性能日志：按 runId/步骤记录可靠耗时和摘要，不新增页面。两种性能模式使用单调计时器，不把并行/嵌套相加为总耗时，不拼接不同时间源为精确端到端耗时，缺数据标未采集。

## 共用实施边界

复用现有排查、logger、组件和计时能力，低侵入、不改变业务逻辑，采集异常不影响业务。额外采集主动启用，敏感信息白名单脱敏、限量。业务定义步骤，不将示例数据写死到通用组件；地图场景仅在目标项目存在时接入，否则用本对话当前功能验收。建议依据真实数据，不编造根因或实际验证结果。

临时探针继续使用 TEMP-DIAG、清理清单和本会话结束取证时移除提醒；正式诊断能力与临时探针区分，关闭不等于移除，不承诺后台或跨会话提醒。

## 交互与范围

- 默认动作 `add-logs` 为纯提示词，启用并固定；默认常用组紧邻 Bug排查，开发组也提供入口。点击只插入草稿，由用户明确发送，不启动自动工作流。
- 已保存动作和分组布局不自动覆写；旧用户在按钮设置“补齐缺失预设”后保存，开发组可见；如需在自定义常用组显示，由用户自行勾选。
- [默认提示词](<../../../src/client/actions.ts>)是全文权威：聚焦一个具体问题，缺复现条件先询问；最小日志点对应待验证假设，不顺带修业务逻辑。
- 复用 logger、关联 ID 和已有开关，默认关闭、局部启用，脱敏、限频/采样并保护参数求值；禁止全局 debug、擅自操作生产或提交推送。

## 临时与清理约定

- 以问题专属 `TEMP-DIAG` 标识标记新增日志，并记录用途与移除条件。
- 完成时交付日志点/假设、复现及启停/取证步骤、针对性验证结果、可搜索的清理清单（日志、临时开关、配置及文件位置）；关闭开关不等于移除临时代码。
- 加日志完成后立即提醒用户在复现取证或排查结束后移除；本会话后续获得复现结果、定位/修复或结束排查时再次提醒。清理先确认范围，不删除原有日志或他人改动，清理后针对性验证。
- 未清理必须标注待清理，交接携带清单；这是发给 Agent 的行为约定，不是持久待办、后台定时器或跨会话自动提醒，不声称系统保证强制清理。
