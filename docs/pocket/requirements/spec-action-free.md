# 固化需求按钮可直接使用

状态：accepted（2026-10-26 用户改判：取消置灰，按钮更自由）

范围：Skill Launcher 的 `spec`（固化需求）动作。

- 按钮始终可点击，不检查当前会话是否完成过「需求讨论」或「可视化讨论」，也不要求已形成讨论结论。
- 点击后按常规插入 `/to-spec` 草稿；不再显示“请先完成需求讨论”一类前置条件提示。
- 仅保留通用禁用规则：输入框不可用、配置未加载、插入请求处理中，以及其他按钮共用的限制。
- 下一步推荐仍只是建议：上一回合形成需求结论时，`spec` 仍可能被标记为推荐，但不影响点击。
- 原“讨论结论解锁、会话隔离”规则已废止，历史决策见 [固化需求按钮的前置条件](spec-action-gate.md)。

实现依据：Launcher 不再从可见会话历史重建讨论状态；`chatEntries` 恢复为只读取最近一次已完成的问答，按钮禁用条件只剩通用的 `available`。`requirementsReady` 及其判定逻辑、`specPrerequisite` 提示文案已删除；阶段链接仍用于生成下一步推荐，不拦截按钮。此规则仅约束按钮，用户仍可手动输入 Skill 命令。

回归入口（Node.js 24+）：`npm run test:spec-action`，覆盖空历史、待确认讨论、中断/失败回合、运行中会话下的按钮可点击与插入行为，以及通用禁用规则仍然生效。
