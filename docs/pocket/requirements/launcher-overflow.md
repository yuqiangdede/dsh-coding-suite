# 开发分组改名与更多按钮

状态：accepted。来源：2026-10-28 用户要求“需求开发”分组改名“开发”，按钮过多时增加更多；随后要求按可用宽度先铺满、确实放不下才显示“更多”。组内展开/收起及测试边界已确认。

## 交互约定

- “需求开发”显示名改为“开发”，英文为 `Development`；沿用 `development` 分组 ID。发射器分组开关、标题与设置界面共用字典，不修改已保存的按钮或分组配置。
- 常用、开发、文档编写、其他各组独立折叠。默认按该行可用宽度依次放入按钮，只有剩余按钮确实放不下时才在行尾显示“更多（剩余数量）”；全部放得下时不显示更多。禁用项不参与显示，也不计入剩余数量。
- 点击“更多”在组内原位展开全部按钮，出现“收起”；点击收起回到当前行宽下的可见数量。展开时按钮按既有换行规则排布，窄屏不截断内容。
- 展开是组件内的临时展示状态，不保存 Host 配置、不插入草稿或发送消息；各组互不影响，刷新/重新挂载后收起。只读设置或执行锁不妨碍浏览展开项，动作本身仍遵循既有禁用与草稿插入规则。
- 折叠区存在推荐动作时，“更多”显示提示点，现有推荐说明仍显示完整动作名称；不重排按钮。更多/收起使用原生按钮、组名限定的无障碍名称及 `aria-expanded`，支持键盘操作。
- 没有新增动作、Skill 或提示词；仍由现有按钮设置管理顺序、成员与启用状态。

## 常用分组显示设置（2026-10-28）

- “显示分组”增加常用开关，设置页也可勾选常用；常用组内提供隐藏按钮，隐藏后可通过显示分组开关恢复。所有分组可独立显示或隐藏，隐藏不改变按钮成员、顺序或提示词。
- 默认显示常用；旧布局缺少 common 字段时按显示处理，显式 true/false 随布局保存、导入和导出。只读或保存失败时沿用现有分组设置行为。

## 页面内编辑常用（2026-10-28）

- 显示分组一行提供“编辑常用”，无论常用组是否显示均可进入。编辑面板列出所有已启用的按钮（包括自定义按钮），勾选或取消后点击保存生效；取消放弃本次选择。编辑时隐藏动作分组，避免误触执行。未启用或暂时缺失的成员保留原配置；新勾选的按钮追加到已有顺序。
- 仅保存布局中的常用成员，不修改动作本身或分组显示状态。只读、配置无效或没有版本时不能进入编辑；版本冲突或保存失败时保留编辑内容并提示，取消后可重新进入。常用成员仍受布局上限 100 个约束。
- 编辑面板按需求、开发、文档、其他分组展示已启用按钮，沿用各分组的成员与顺序，不受分组显隐影响；属于多个分组的按钮在各组显示并共享勾选状态。没有业务分组的常用预设及自定义按钮归入“其他”，空组不显示。

## 开发分组补充 Bug排查（2026-10-28）

- 按用户要求，`bug`（Bug排查）在保留常用组默认位置的同时进入开发分组，排在「编码」之后、「增加日志」之前，与「增加日志」「分析日志」相邻；同一 action ID 在两个分组各显示一次，共享同一 Skill 与提示词。
- 这是显示层成员变更，不新增或复制按钮，不修改提示词、Skill 绑定、启用状态或用户已保存的布局；开发组由 14 项增至 15 项，可见数量按行宽计算，无法测量 DOM 的宿主回退前 8 个（包含 Bug排查），展开/收起与推荐提示点规则不变。
- 由于 `bug` 已有业务分组，编辑常用面板把它归入开发组，不再作为未分组预设追加到其他组；常用组成员及顺序不受影响。

## 按可用宽度展示更多（2026-10-28）

- 用户以 968px 宽截图指出「开发」行只放 8 个就出现「更多（6）」，但行尾仍有空位；要求先铺满可用宽度，确实放不下才显示更多。该要求取代此前“固定前 8 个、不引入窗口测量”的规则。
- 折叠行按可用宽度累加按钮宽度与间距，仅在剩余按钮放不下（含行尾“更多”按钮所需宽度）时折叠；全部放得下时没有更多按钮。计算保留 1px 余量，避免亚像素宽度把“更多”挤到下一行。
- 浏览器通过组内离屏测量行读取每个按钮的实际宽度（与可见按钮同一套样式、字号和文案），并观察行宽变化重新计算；测量行 `aria-hidden`、按钮禁用且不占布局，不参与 Tab 顺序。
- 测量只决定可见数量，不保存、不改写成员、顺序、启用状态或已保存布局；推荐提示点、展开/收起、组名限定的无障碍名称与键盘操作不变。
- 无法测量 DOM 的宿主（stub 渲染、非浏览器环境）回退为每组前 8 个，保持既有行为。
- 实现：[发射器](<../../../src/client/Launcher.tsx>)、[宽度计算](<../../../src/client/launcher-layout.ts>)（`fittedActionCount`）、[样式](<../../../src/client/Launcher.module.css>)。
