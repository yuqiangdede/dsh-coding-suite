# 自动编码入口与双链路

状态：accepted。范围：插件发射器与内置 `coding-workflow`；依据：2026-10-28 用户确认在「显示分组」同一排提供默认手动的模式切换，自动判断 Bug 修复或需求开发。

## 交互与授权

- 「手动 / 全自动」切换位于「显示分组」同一排。没有活跃工作项时默认手动，不持久化自动启动意图；有活跃工作项时以 Host 的 mode 为准。
- 切换自动只选择模式，不发送消息、不开始或恢复执行。自动模式提供「准备全自动任务」：核对 Skill 可用后，在草稿开头插入 `/coding-workflow` 和流程指令，保留原有目标文字；用户手动发送才授权开始。
- 草稿存在选区、光标不在开头、已有斜杠指令或 Skill 缺失时不覆盖原文。活跃任务期间禁止重复准备及冲突的单阶段动作。
- 转手动先暂停确切关联的原生 Goal，再将现有 Host 工作项设为 manual（Host 切换会暂停工作项）；任一步失败不宣称切换成功。手动接管保留工作项及阶段证据，须通过面板恢复 Host 工作项后继续原任务，不解除任务的范围/验证守卫。
- 仅凭精确的 `[coding-workflow:<taskId>]` 前缀关联 Goal，不暂停或覆盖其他 Goal。会话仍在执行却无法确认关联时，要求先通过原生停止控件停下。
- 面板暂停/取消同步暂停关联 Goal；自动任务的显式继续恢复 Host 与关联 Goal，Goal 恢复失败时尝试重新暂停 Host 并显示错误。批准后若 Goal 仍暂停，提供明确的继续按钮，不自动恢复。
- 刷新或重启仅恢复状态展示，不自动开始或继续。缺少 Host Remote 时普通按钮及模式准备仍可显示；不据此假定 Host 工具存在，Agent 必须先核实工具。缺少 Host 工具时停止说明，不静默切换为脚本权威。

## Agent 选择链路

判定依据是用户目标、上下文、既有行为约定与真实代码证据，不由前端关键词分类。Agent 先说明分类及理由；无法确定或行为约定不明时提问。包含行为约定变化的“Bug”按需求链路处理，混合任务先明确拆分边界。

| 链路 | 编码前的必要工作 | S1/S2 |
| --- | --- | --- |
| Bug 修复 | 建立复现、明确期望与实际、定位根因、制定回归测试与最小修复计划 | 仅恢复既有行为且不改约定时，允许分别带证据理由显式跳过；否则走完整链路 |
| 需求开发 / 行为约定变化 | 澄清范围与验收条件，形成规格与设计，再登记实施计划 | 不跳过需求与规格设计 |

两条链路共用 S3 计划及精确文件范围、S4 实现、S5 结构化审查、必要的 S6 修复、S7 所有登记的真实 test/build 验证、S8 单次本地提交、S9 交付报告。禁止 push、PR、部署；不允许因选择 Bug 链路而绕过审查或验证。分类与修复方法属于 Agent/Skill 规程；Host 继续校验阶段、证据、范围与验证结果，不新增未经批准的分类 schema。
