# Step 09：页面-流程-状态-权限一致性 Gate

## 定位

这是进入 UI/原型输出前的最后一道业务一致性 Gate。

只做校验，不新增页面、不重新设计流程、不修改权限模型。发现问题后回退对应阶段修正。

## 前置条件

必须同时存在：

- 已评审的 PRD。
- 页面清单和页面规格。
- 核心流程和异常流程。
- 核心对象及状态流转。
- 角色、数据范围和操作权限。

缺任一项则 `FAIL`。

## 校验矩阵

逐条检查：

1. **流程步骤 ↔ 页面/操作入口**：每个需要人工参与的步骤都有可达入口。
2. **页面操作 ↔ 流程推进**：按钮/动作有明确前置条件和结果。
3. **状态 ↔ 可用操作**：不同状态下允许/禁止操作明确。
4. **角色 ↔ 页面可见性**：看得到与看不到有依据。
5. **角色 ↔ 操作权限**：可见不等于可操作。
6. **数据范围 ↔ 页面数据**：角色能看到的数据范围与 PRD 一致。
7. **异常流程 ↔ 页面承载**：驳回、撤回、超时、失败、部分成功等有入口或明确系统归宿。
8. **PRD ↔ 页面规格**：页面不得出现 PRD 没有依据的新规则，PRD 必要能力不得在页面消失。
9. **终态/悬挂态 ↔ 页面**：不存在状态已经发生但没人能继续处理的“死单”。

## 问题输出要求

每个问题必须指出：

- 涉及流程步骤。
- 涉及页面/PageId。
- 涉及状态。
- 涉及角色/权限。
- 不一致点。
- 上线后后果。
- 应回退到哪个阶段。
- 严重程度：阻断 / 高 / 中 / 低。

## Gate 结论

- `PASS`：不存在阻断问题，页面/流程/状态/权限闭环。
- `CONDITIONAL PASS`：只剩不改变核心业务的明确待办，并记录关闭条件。
- `FAIL`：存在无入口、越权、状态冲突、异常无归宿、PRD 与页面核心规则不一致等问题。

## 输出

### Gate ③ 结果

- 状态：PASS / CONDITIONAL PASS / FAIL
- 关键不一致问题
- 异常流程承载问题
- PRD 与页面差异
- 必须关闭项
- 回退位置

只有 `PASS` 或满足关闭条件的 `CONDITIONAL PASS` 才允许进入 Step 10。
