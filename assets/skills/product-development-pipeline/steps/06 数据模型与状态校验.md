# Step 06：数据模型与状态 Gate ②-B1

## 目标

在枚举异常和生成 PRD 前，先确认核心业务对象、关键字段语义和状态模型能够承载真实流程。

本步骤审的是概念/业务数据模型，不写 SQL，不做数据库选型。

## 输入

- 已通过模块 Gate 的方案。
- 核心业务对象及关系。
- 主流程。
- 状态框架和权限框架。

## 检查项

1. 核心实体是否齐全且职责单一。
2. 关键业务事实是否有明确归属，是否被多实体重复表达。
3. 可被流程推动的对象是否有明确状态。
4. 状态是否混入“结果、标记、权限、是否存在”等多个维度。
5. 每个状态是否有进入条件、允许操作、退出条件和终态/回收路径。
6. 是否存在非法跳转、永远悬挂或只能靠线下人工解释的状态。
7. 跨实体状态是否存在隐式同步和强耦合。
8. 页面/流程是否依赖模型中不存在的“隐形状态”。
9. 空值、默认值、时间字段是否被用来暗示业务状态。

## 每个风险必须说明

- 涉及实体/字段/状态。
- 当前语义。
- 风险类型。
- 触发场景。
- 会返工的流程/页面/接口/历史数据范围。
- 建议动作：Accept temporarily / Clarify before freeze / Block proceeding。

## Gate 结论

- `PASS`：对象和状态模型足以进入异常补全。
- `CONDITIONAL PASS`：剩余问题不改变核心状态机，并有明确关闭条件。
- `FAIL`：状态缺失/过载/死路、实体职责冲突或隐式状态会导致后续设计失真。

## 输出

- Gate 状态。
- 数据与状态风险清单。
- 必须修正的状态/语义问题。
- 可接受风险与关闭条件。
- 失败时回退 Step 04/05。

通过后进入 Step 07；必须先稳定状态，再枚举异常。
