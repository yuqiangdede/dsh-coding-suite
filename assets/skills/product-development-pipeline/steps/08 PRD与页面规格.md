# Step 08：PRD、独立评审与页面规格

## 定位

本阶段只消费 Step 01–07 已确认的业务设计，不再重新做需求澄清、需求分析、模块划分、状态设计或流程设计。

执行顺序固定为：

`已确认设计 → prd-writing → requirement-review → 页面规格投影`

## 前置条件

- Gate ① 已通过。
- 模块边界 Gate 已通过或有明确条件。
- 核心对象与状态已稳定。
- 核心流程及重要异常已有明确归宿。

未满足时必须回退，不得在 PRD 中偷偷补业务设计。

## A. 生成 PRD

优先使用 `prd-writing`。

PRD 至少覆盖：

- 背景、目标、用户和范围。
- 核心对象和业务规则。
- 主流程与异常流程。
- 状态流转。
- 角色、数据可见范围和操作权限。
- 字段/数据规则。
- 页面与交互需求。
- 验收标准。
- 风险、依赖和待确认事项。

## B. 独立需求评审

PRD 形成后立即切换到 `requirement-review` 审计视角。

必须输出：

- S0 阻塞项。
- S1 高风险项。
- S2 一般问题。
- S3 优化建议。
- GO / CONDITIONAL GO / NO-GO。

`NO-GO` 时停止本阶段并回退对应步骤；作者不能自行修改后直接宣布通过，修改后要再次评审。

## C. 页面规格投影

仅在评审为 `GO` 或满足明确条件的 `CONDITIONAL GO` 后执行。

页面来自已确认业务任务，不重新设计业务。

每个页面至少输出：

- PageId / 页面名称。
- 使用角色与进入场景。
- 页面目标。
- 页面入口和返回路径。
- 布局区域。
- 核心字段/表格列/筛选项。
- 主要操作。
- 操作对应的前置状态和结果状态。
- 可见权限 / 操作权限。
- 正常、空、加载、失败、禁用等必要状态。
- 涉及的异常处理入口。
- 是否需要 UI 效果图或可运行原型。

## 全局页面配置

记录：

- 标签语言。
- 示例数据语言。
- 已确认全局视觉约束（如有）。

这些只是展示配置，不得反向改变业务规则。

## 输出

1. PRD 文件/内容。
2. 独立评审结果和关闭项。
3. 页面清单。
4. 页面规格。
5. 全局展示配置。
6. 待确认但不阻塞项。

完成后进入 Step 09 页面-流程-权限一致性 Gate。
