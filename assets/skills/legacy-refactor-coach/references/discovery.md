# 环境识别与遗留系统审计

P0、P1 使用。按源码入口、调用链和数据路径取证，范围外标未覆盖。

## P0：项目初始化与重构基线
首先识别项目真实情况。
包括：

- Git 仓库及当前分支。
- 工作区是否存在未提交修改。
- 原工程路径。
- 计划使用的新工程路径。
- 是否需要原位改造或独立创建新项目。
- 后端 Java 版本。
- Spring Boot 版本。
- Maven 或 Gradle。
- 前端 Vue 2 或 Vue 3。
- JavaScript 或 TypeScript。
- Vite 或 Webpack。
- npm、pnpm 或 yarn。
- 前端 UI 组件库。
- 数据库类型和版本。
- Redis、消息队列、定时任务等中间件。
- 外部系统依赖。
- 运行和部署环境。
- 构建命令、启动方式及测试命令。
- 当前系统是否仍然运行。
- 是否存在生产数据兼容要求。
- 是否有不可中断的业务能力。
- 需要保留或删除的功能是否已经明确。
必须区分：

**已从源码确认、已从运行结果确认、用户声明、合理推测、尚未核实。**
禁止把推测写成事实。
对于没有必要立即决定的参数，可以先采用可撤销的默认方案。
只有涉及核心业务取舍、不可逆操作或者影响整体方案的重要问题，才向用户请求决策。
初次调用时，优先完成环境识别与基础信息收集。
如果用户没有明确要求开始执行，不修改业务代码。

## P1：历史工程全面审计
针对 Java Spring Boot 和 Vue 同时进行审计。

### 后端审计
至少检查：

- 工程模块与包结构。
- Controller、Service、Mapper、Repository 的职责。
- 核心业务流程。
- 领域模型与数据库实体混用情况。
- 模块间依赖、循环依赖。
- 复杂业务方法和超大类。
- 静态工具类和全局状态。
- 重复实现和隐式依赖。
- 配置体系与环境差异。
- 数据库表、视图、存储过程和读写路径。
- SQL 性能风险。
- 事务传播、边界和一致性。
- 缓存策略与失效逻辑。
- 并发控制、锁与线程池。
- 消息队列、重试、幂等与补偿。
- 定时任务。
- 文件与外部服务调用。
- 鉴权、权限、输入校验。
- 异常处理与日志。
- 测试覆盖情况。
- 构建与部署情况。
- 高风险第三方依赖。

### 前端审计
至少检查：

- Vue 版本及工程配置。
- 页面和路由结构。
- 组件依赖关系。
- 超大组件及重复组件。
- API 请求分布。
- 业务状态与 UI 状态。
- Vuex、Pinia 或其他状态管理。
- 组件间通信。
- 路由与权限控制。
- 数据校验和错误提示。
- UI 逻辑与业务逻辑耦合。
- 重复代码和公共组件。
- 首屏加载、资源体积和懒加载。
- 无效请求和重复渲染。
- 定时器、事件监听器及资源释放。
- 前后端 API 契约。
- 主要页面的实际交互行为。

### 必须输出

- 系统功能地图。
- 关键业务调用链。
- 后端模块依赖关系。
- 前端页面与组件关系。
- 数据流和数据所有权初步分析。
- 外部依赖清单。
- 代码风险清单。
- 技术债清单。
- 旧系统构建与测试基线。
- 不确定事项清单。
依赖关系图可以使用 Mermaid。
要求源码分析尽可能提供文件路径、类名、方法名和关键代码位置。
不要只输出抽象评价，例如“系统耦合度很高”，而不提供证据。

## 证据记录

每项记录证据类别、文件路径/类/方法/行号或命令、版本、结论、可信范围与待核实项。构建失败保留退出码和脱敏错误，区分工具缺失、配置缺失与代码失败。运行验证前检查环境与副作用，不能默认连接生产。
