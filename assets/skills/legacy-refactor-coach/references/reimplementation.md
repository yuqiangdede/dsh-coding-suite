# 重新实现：功能选择到新模块交付

本分支适用于用户选择从零实现，或明确要求按照功能清单重建。与指导/执行模式正交：选择此目标本身不等于授权修改代码。按下列 R0–R4 引导，对应 P0–P7；不把渐进迁移步骤当成必选。状态和证据沿用 templates.md，正式资料仍按项目文档规则预览并确认。对话只问当前决策必需的问题，已有答案不重复询问；可以并行完成不依赖决策的调查。

## R0 定位现有功能清单（P0–P1）

先读取项目规则、文档布局和索引，确定范围与 Git 工作区。查找现有权威需求、功能目录、产品说明、验收资料及用户指定资料；记录路径、状态、范围、版本/日期、证据和与当前代码的差异。交叉检查路由、页面、接口、任务、权限、数据和外部集成等实际入口，区分有效功能、历史/停用项、文档计划项和未知项；不因文档存在就声称清单完整，也不因未发现入口就认定功能不存在。列出覆盖边界与未核实区域。

没有可用清单、清单明显缺项或过期时，发现当前环境中可用且适合源码反推功能清单的其他 Skill，按该 Skill 的调用机制与前置要求调用，优先处理缺口；例如可用时考虑 requirements-spec 的当前系统源码反推 L1。提供已知的项目路径、范围及参考资料状态，遵守其输入要求，不伪称用户已确认没有参考资料。若宿主不支持调用、没有合适 Skill，或其必要输入缺失，说明原因及所需信息，继续能独立进行的源码盘点，不安装或虚构调用结果。产出按功能去重的候选清单，并合并现有清单及新证据，不创建第二份正式权威文档。

候选项至少包含稳定 ID、业务功能和用户场景、入口/角色、关键行为与异常、业务规则、数据和上下游依赖、来源及可信度、现状/未知、建议。明确清单仅覆盖已调查范围；存在重大空白时先调查或呈现缺口，不声称全量完整。达到用户可判断去留的证据后展示清单。

## R1 用户确认功能范围（P2）

按业务模块展示编号清单及建议，支持逐项或按模块批量选择“保留 / 不纳入本次 / 待定”，允许用户补充未发现的功能和目标行为；已有明确选择直接沿用。不纳入本次仅定义新系统范围，不授权删除旧功能、数据或文档。提示关联依赖、权限、共用能力、数据及外部调用方，发现冲突时给出可选处理及影响，不自动扩展或剔除范围。

汇总保留项、排除项、待定项、关键规则与验收场景，并请用户明确确认本批范围；记录选择及依据。待定项不默认为排除，影响本批实现的关键业务或依赖未定时暂停相应部分，继续独立事项。实现依据已确认目标契约而非自动复制旧缺陷；必要时请用户决定旧行为是否应保留。

## R2 技术选型与方案确认（P3）

先识别用户已指定的技术、团队能力、运行平台、预算、现有基础设施、性能、安全、数据及兼容要求。明确前端、后端、语言/运行时、框架及版本、构建包管理、数据库、部署和测试中实际需要选择的项；缺少的约束标未知。提出适合项目规模的推荐方案，关键决策比较可行替代项、维护成本、兼容、风险和依据；无须为无关组件强行选型。已有技术不默认继承，也不默认升级；核实关键版本及兼容证据，无法核实时标待核实。

提出新模块所在仓库与路径、模块职责和边界、功能到模块的映射、接口及数据策略、与旧系统隔离方式、验证方式和实施顺序。模块默认在现有项目中新建独立模块；仅在技术或仓库限制下推荐独立工程，说明理由并由用户选择。展示方案与主要取舍，请用户确认技术选型及模块位置；实质变化重新确认，已确认且仍有效的选择不重复询问。

## R3 新模块实施（P4–P6）

在用户明确要求实施且确认当前批次范围、技术方案、模块位置后，核实目标路径、未提交改动、命名和构建集成方式；不得覆盖现有文件。先创建新模块的最小可构建骨架和验证方式，再按依赖及业务价值挑选首个可验收功能单元。逐单元依据确认的业务规则设计接口、数据、权限、异常和验收测试，从零编写实现，不复制、移植或调用旧业务实现；旧系统仅用于取证，是否保持外部契约及迁移历史数据须另行明确。通用第三方依赖按已确认技术方案使用。

每个单元完成相关自动化测试和必要集成验证，记录命令、结果与未覆盖项，再推进下一个已授权单元。若授权只覆盖计划或某个阶段，不把技术选型或范围确认当作全量编码授权；在已授权范围内连续工作，不逐项重复征求确认。共享构建或入口的最小接线须在确认方案覆盖内；不自动切换生产流量、删除旧模块、迁移生产数据、部署、提交或推送。

## R4 整体验收与后续处理（P7–P8）

按保留功能清单逐项核对已实现、测试通过、未完成和待定项，验证关键跨模块流程、权限、错误处理及必要非功能要求；将未执行、失败与不适用分开记录。输出新模块路径、功能覆盖及实际验证结果、已知缺口和下一步。若需要接入旧系统、数据迁移、切换或退役，另列方案、依赖与回滚并按风险取得相应授权；不需要时标不适用，不强制新旧并存或迁移。

## 进度恢复

状态中记录目标为重新实现、当前 R 阶段与对应 P 阶段、清单来源及覆盖缺口、功能选择和批准记录、技术选型及模块路径、授权范围、已完成单元和验证结果。恢复时核查源码及决策是否变化，只退回受影响步骤，不重复已有有效确认。
