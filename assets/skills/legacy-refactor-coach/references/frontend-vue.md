# Vue 专项

前端审计、P4 基线及 P5/P6 实现时使用。审计清单见 discovery.md，目录及 API 协作规则见 architecture.md。

### Vue 前端
根据 Vue 版本及已有项目体系考虑：

- ESLint。
- Prettier。
- TypeScript 类型检查。
- Vitest 或 Jest。
- Vue Test Utils。
- Playwright。
- API 契约检查。
- Bundle 分析。
优先兼容项目实际版本。
不要为引入测试工具而无根据地大规模升级前端工程。

## 前端
特别强调：

- 页面组件、业务逻辑和 API 请求合理分离。
- 避免在组件中直接散落复杂后端请求逻辑。
- 合理提取 Composables 或 Vue 2 对应复用机制。
- 明确页面局部状态与全局业务状态边界。
- 防止组件间通过全局状态形成隐式耦合。
- 避免重复请求和不必要的重新渲染。
- 正确处理组件卸载后的异步响应与资源释放。
- 防止路由鉴权和后端授权规则出现不一致。
- 页面改造应保留用户确认的交互行为。
- 不因架构重构而擅自大范围改变 UI 设计。

## 版本适配与验证

先读 package.json、锁文件、Vue/构建器/组件库实际版本。Vue 2 采用现有兼容复用机制，Vue 3 按需提取 composables。不要为重构强制迁移 Vuex/Pinia、JS/TS、Webpack/Vite 或 UI 库。局部状态留在页面或组件，跨页业务状态说明所有者、更新入口与释放条件。

API 层集中处理协议、错误和取消；防止快速切换时旧响应覆盖新状态。卸载时释放事件、订阅、定时器与请求，检查 KeepAlive、路由切换和重试行为。测试加载、空数据、错误、权限、重复提交与竞态。前端鉴权负责交互，后端执行最终授权。保留已确认交互与视觉约束。

性能测量覆盖首屏、资源体积、懒加载、重复请求、重复渲染、长列表和内存，统一浏览器、网络、设备与数据条件。

## 前后端联合验收
每个完整业务功能必须评估：

- 前端入口。
- 后端接口。
- 权限要求。
- 参数格式。
- 响应结构。
- 数据库操作。
- 异常处理。
- 页面结果。
- 失败及边界场景。
不能只验证后端单元测试就宣称整个功能完成迁移。
