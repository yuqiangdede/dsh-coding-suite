# 项目文档单一权威位置与 Pocket 路由协议

本文件供初始化、需求、设计、接口、知识提炼、补充文档、验收、交接和 Pocket 维护 Skill 共用。**Pocket 是知识索引与缺省补位目录，不是强制迁移目标，也不能成为同一内容的第二份权威副本。** Markdown 随项目 Git 版本管理；本协议不引入 RAG、数据库、后台任务或新的 UI 按钮。

## 0. 初始化产物目录契约（所有功能生效）

- 目标项目必须先经用户确认并创建 `docs/agents/document-layout.md` 与所登记的中间工作目录 `README.md`。**所有 Skills、提示词和流水线**在读取、创建、修改或依赖需求/设计/API/数据库/验收/交接/评审/Gate/转换等文件型产物时，先读根 Agent 指令、布局表与知识索引。旧默认输出路径（例如 `docs/Requirements/`、`.scratch/` 或 `knowledge/`）只有布局明确允许时才可使用，不能让各 Skill 各自建目录。
- 正式文档优先已确认的主题权威文件；缺少时才使用布局登记的对应类别回退路径，不能产生双份现行正文。中间成果、分析稿、来源快照、评审结果、检查点和转换部件进入**任务级工作区**（通常是 `docs/_work/<task-id>/`）；任务缓存进入该工作区 `tmp/`。外部工单沿用 Issue Tracker，不将工作副本冒充远端权威。
- 初始化展示所选目录、既有文档映射、冲突和实际文件清单，取得确认后**创建布局文件及中间工作目录 README**，不要求创建所有未来分类空目录。布局存在冲突、文件缺失或用户不同意迁移时报告并停止新的文件写入；已有文件不搬迁。
- 不需要文件的普通分析不强制落盘；正式文档创建、合并、迁移、删除和内容变更继续执行差异预览、确认、索引更新与历史留存。

## 1. 写入前的权威位置发现

1. 读取目标项目根目录已生效的 `AGENTS.md`、`CLAUDE.md` 及项目文档约定；读取已有知识索引（如 `docs/README.md`、`docs/pocket/README.md` 或项目自定义索引），但**不得假设它一定存在**。
2. 枚举真实存在的需求、设计、接口、部署运维、ADR、术语及历史记录文档；包括根目录 `README.md`、`CHANGELOG.md`、`docs/**` 和项目约定的其他位置。对候选文件检查业务范围、状态、版本、链接和当前编辑情况。
3. 对本次要写的**每个主题**分别确定位置，优先级依次为：
   - 用户已经明确指定、且不与已确认权威冲突的路径；
   - 项目现行规范、Agent 指令或知识索引明确声明的权威路径；
   - 已有、内容仍有效、覆盖该主题的文档原路径（在原位置增量编辑）；
   - 项目现有对应分类目录（按项目命名规则创建一个文件）；
   - 上述均不存在时，才使用 `docs/pocket/` 下对应分类按需补位。
4. 位置存在冲突、两份内容都声称有效、路径含糊或源文件有未提交修改时，列出候选、差异和建议，**不要擅自选择、覆盖、搬迁或把历史稿提升为现行权威**。
5. 不因为安装插件、运行初始化或新增文档 Skill，就批量创建 `docs/pocket/` 的分类空目录；不得生成与已有文档等价的 `knowledge/`、`docs/Requirements/`、`docs/Design/` 第二份内容。已有这类目录本身可以是权威，不能仅因名称而搬迁。

## 2. Pocket 索引如何使用

- 项目已有索引：优先维护已有索引，并用任务/领域/模块 → **真实权威文件路径** 建立指针。没有必要再生成一个同功能的索引。
- 项目已有 `docs/pocket/README.md`：继续使用它作为统一导航，**正文仍在各自已确认的权威位置**；索引仅提供摘要、状态和链接，不复制正文。
- 项目没有索引：初始化可在确认后创建最小的 `docs/pocket/README.md`（以及确有需要的元规则）；如已有其他文档目录，Pocket 只做索引和缺失主题的补位，不迁移已有内容。
- 每项索引至少记录主题、当前权威路径、状态（accepted/current、pending、superseded/deprecated）与替代文档（适用时）。只有真实存在的文件才能生成可点击链接；尚未建立的类别以文字说明，不伪造链接。
- 小型项目按索引确定性加载相关 Markdown；规模大且真正遇到检索瓶颈时才另行评估本地 RAG，RAG 索引不成为知识真值源。

## 3. 多个 Skill 协同写文档

- 需求固化、设计、接口文档、知识提炼、补充文档、验收及交接使用**同一份权威路径映射**，不得每个 Skill 各自创建一套分类文件。Skill 自身的默认输出目录只在目标项目无更明确规则和现有权威时生效。
- 独立交付报告/快照/临时分析稿可放用户指定的工作目录，但必须标识为派生产物或草稿；不和正式规范同时宣称 current。交接文档优先链接现有需求、设计与运维资料，只补缺失章节，不整篇复制。
- 对拟更新的正式文档列出目标文件、来源、修改原因和影响范围，**先展示差异预览**。创建新权威文档、替换事实、迁移、合并或删除前取得明确确认；不自动提交或推送目标项目的更改。既有批准不等于后续重大业务规则修改的授权。
- 更新确认后仅修改对应权威文件，更新相关索引、引用与状态。存在两个冲突的有效版本时先报告冲突，不依据代码行为自动修改已批准需求。
- 源码、可执行测试、数据库迁移、部署配置和依赖锁文件继续代表**当前实现事实**；文档代表已确认的需求/决策。两者冲突应标明差距，不偷偷以一方覆盖另一方。

## 4. 渐进式加载和周期整理

- 常驻 Agent 指令只保留索引入口和最关键的约束；按任务先读索引条目，再读相关需求/ADR/运维说明，最后按需要读取证据和历史。禁止默认把整个文档目录塞入上下文。
- 重要需求或架构变更、合并 PR 后检查受影响文档与链接；建议每月人工运行 `pocket-maintenance`，产生重复、过期、冲突、断链、孤立文档候选报告。
- 清理必须有源码、决策或后继文件依据。归档/删除/合并前展示差异并确认，保留 Git 历史、ADR 决策原因、状态及继承链接。**不创建自动清理定时任务**。

## 5. 完成检查

输出本次权威路径表（主题、复用位置或 Pocket 补位、现行状态、变更摘要）、已展示且获确认的差异、更新的索引、遗留冲突/未确认项，以及实际完成的文件/链接检查。无法检查的项目如实写明，不声称已经验证。
