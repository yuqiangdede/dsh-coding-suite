# 补充业务排查：共享实施约定

只针对本对话已完成编码的功能补充排查能力。先核对会话、变更、真实调用链和项目约定；未完成或目标有歧义时询问，不猜测、不扩展到全项目。例子中的地图定位、MBS、IRDS 只有目标项目真实存在时才接入，否则选择当前功能验证，不能为演示虚构业务。

读取项目 Agent 指令、文档布局与知识索引。正式资料沿用现有权威位置，变更先预览并确认；分析、验证报告等文件进入布局登记的任务工作区。先检查已有 logger、关联 ID、排查数据、组件与计时能力，增量复用；四种模式共用步骤采集和基础数据，不重复开发框架，不引入监控平台、工作流引擎、历史统计或告警。

## 采集语义

每次业务执行有独立 runId/关联 ID，按实际顺序记录步骤 ID、名称、服务/接口、关键脱敏输入输出、数据来源、技术状态、业务结果、摘要、异常、必要说明及可用耗时。步骤由业务定义，支持条件分支、提前结束、备用查询、异步及并行；不采集所有内部方法。

统一展示状态：成功、异常、失败、已跳过、未验证。异常可表示可恢复警告，失败表示操作未完成；无数据是业务结果，不等于接口失败。示例中 WARNING 必须明确映射为异常/警告，不引入相互矛盾的状态集合。未走分支可省略或明确已跳过；缺反馈是未验证，不能标成功。回退记录原因、来源、执行结果；最终状态依据真实业务终点反馈，接口成功或获取到坐标不证明地图已移动。

优先沿用现有模型，可按项目规范映射 functionName、status、conclusion、steps、suggestions；步骤含 id、name、service、status、technicalResult、businessResult、request、response、summary、durationMs 等必要字段。未知耗时用 null，不用 0 冒充。示例只放测试/演示隔离区，不写死在通用组件，不作为实际诊断结果。

## 非侵入和取证

不改变业务分支、返回值、异常传播和副作用，不为采集重复调用业务接口。采集失败不能影响业务；开关须覆盖参数求值、序列化及异步上报错误，控制开销与内存，长任务和取消也要释放记录。仅主动排查时启用必要额外采集；复用访问控制和开关，输入输出白名单脱敏、截断限量，禁止令牌、Cookie、口令和隐私进入页面或日志。

建议只陈述有证据支持的现象与下一步检查，不认定未经验证的根因。没有问题或证据不足时不强行生成问题。保留原有业务功能，不顺带修复或优化它，不提交或推送。

## 验证与交付

围绕当前业务验证正常成功、无数据后回退成功、各来源均无数据、接口失败、最后执行失败、缺少最终反馈、条件分支和提前结束；已有地图业务时覆盖原始 MBS 无点位→IRDS 父资源→父 MBS→地图反馈。性能模式还验证并行/嵌套、失败/取消收尾、缺失耗时与不同时间源。验证开关关闭和采集器失败不破坏业务。优先针对性检查；无法真实运行则列未验证项，不宣称运行通过。

交付实际改动文件、公共采集/组件复用方式、当前业务接入与启停方法、实际验证结果及限制、对原功能的影响。临时日志用问题专属 TEMP-DIAG 标识并维护清理清单；完成和本会话取证结束时提醒移除临时代码和配置，关闭不等于移除，不承诺后台或跨会话提醒。正式保留的诊断能力和临时探针应明确区分。
