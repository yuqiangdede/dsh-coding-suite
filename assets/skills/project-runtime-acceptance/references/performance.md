# PERF：数据库、接口、批处理性能

## 规则

| ID | 检查点 | 说明 |
| --- | --- | --- |
| PERF-001 | 高频 SQL 无适用索引 | 从 where/order/group/join 与执行计划判定，不能仅凭字段名 |
| PERF-002 | N+1 查询或远程调用 | 列表项逐条查询/调用，可合并批量 |
| PERF-003 | 无边界分页/大结果集 | 返回全量、内存装载过大、offset 深分页 |
| PERF-004 | 批量删除/更新影响在线流量 | 锁等待、事务大小、限速/分批执行 |
| PERF-005 | 无超时或连接池配置不当 | 等待队列、最大连接数、超时与资源预算 |
| PERF-006 | 热点写入/争锁 | 同一行反复更新、全局锁、热点 key |
| PERF-007 | 重复序列化/转换/转码 | 中间结果复用和资源隔离 |
| PERF-008 | 慢查询/接口缺监控 | P95/P99、数据库执行计划、队列等待与异常速率 |
| PERF-009 | 不合理定时全量刷新 | 改为增量、分批或事件驱动需要考虑复杂度 |
| PERF-010 | 大量无效索引或统计信息陈旧 | 索引写入成本、执行计划变化 |

## 风险评价

静态性能异味先标 `疑似待验证`；有执行计划、峰值数据量、分位延迟或日志时才可给出“造成明显性能瓶颈”的确定性结论。推荐最小变更及前后基线比较（相同数据量/环境/流量）。
