# REC：故障恢复与数据可靠性

## 规则

| ID | 检查点 | 故障模拟方向 |
| --- | --- | --- |
| REC-001 | 异常中断无法断点续跑 | 归档/上传/转码/扫描中断后重入状态 |
| REC-002 | 任务卡死无法发现/接管 | PROCESSING 心跳超时与租约转移 |
| REC-003 | DB 与消息不一致无补偿 | outbox/inbox 或补偿机制、幂等及监控 |
| REC-004 | 外部依赖不可用无降级 | Redis、DB、对象存储、外部 HTTP 的熔断和回退 |
| REC-005 | 备份有但不可恢复 | RPO/RTO 目标、恢复演练证据，不仅有备份脚本 |
| REC-006 | 失败重试重复产生副作用 | 总时限、次数上限、请求幂等标识 |
| REC-007 | 删除/归档过程不能恢复 | 先持久化成功状态，再异步清理，保存失败记录 |
| REC-008 | 进程重启丢失重要状态 | 内存任务、延时消息、调度任务持久化 |
| REC-009 | 恢复期间数据乱序 | 重放顺序、版本号/水位线及去重 |
| REC-010 | 未定义故障处置与告警 | 恢复责任、执行手册、自动化与人工兜底 |

禁止将“建议进行故障注入”视为执行授权。生产故障注入、恢复演练、删除及数据迁移均需独立授权。测试环境做模拟时应使用隔离数据。
