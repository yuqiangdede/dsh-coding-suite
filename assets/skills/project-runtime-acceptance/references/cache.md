# CACHE：全局缓存利用、一致性与刷新节奏

## 缓存资产清单

查找 `@Cacheable/@CachePut/@CacheEvict`、Redis Client、Caffeine/Guava/Ehcache、Django 缓存、cachetools/lru_cache、前端 Query/Redux/Service Worker、本地字典与静态单例缓存。记录 `Key 模板 / 数据归属 / 缓存层级 / TTL / 刷新入口 / 写入来源 / 失效事件 / 用户/租户隔离 / 容量上限 / 命中率证据`。

## 规则

| ID | 核心检查 | 说明 |
| --- | --- | --- |
| CACHE-001 | 相同数据多处重复查询/重复缓存 | 跨模块核实数据语义、隔离粒度与重复成本 |
| CACHE-002 | TTL 与更新频率不匹配 | 根据业务允许陈旧窗口与更新事件，不建议统一 TTL |
| CACHE-003 | 写 DB 未失效缓存 | 修改、删除、事务失败与提交顺序分析 |
| CACHE-004 | 多实例本地缓存不一致 | 分布式通知/版本号/TTL 是否满足一致性需求 |
| CACHE-005 | Key 缺用户/租户维度 | 潜在越权与数据串扰；可升 P0 |
| CACHE-006 | 无界增长 | 最大项、内存成本、淘汰策略、Key 命名膨胀 |
| CACHE-007 | 击穿/雪崩/穿透 | 热点锁、随机过期、负缓存、并发限流 |
| CACHE-008 | 刷新频率过快或全量重算 | 后端负载与数据变化率不匹配 |
| CACHE-009 | 缓存失效时无降级 | Redis 故障导致 DB 雪崩或关键业务不可用 |
| CACHE-010 | 缓存结果不应该缓存 | 实时权限、敏感/高度动态数据导致陈旧风险 |
| CACHE-011 | 错误共享可变对象 | 缓存对象被调用方修改、跨请求污染 |
| CACHE-012 | 缓存与事务写入竞态 | 事务未提交先更新缓存，延迟双删时序等 |

## 决策方法

对高频/重复查询生成候选收益矩阵：`调用频率 × 查询耗时 × 数据稳定性 × 允许陈旧时间 × 内存成本 × 一致性复杂度`。不能仅凭“可以缓存”就要求修改：若数据必须强一致，可考虑请求内复用或批量化，而非共享 TTL 缓存。

运行时证据：命中率、Key 数量趋势、命中/未命中延迟、穿透流量、热 Key、更新频率，需说明指标窗口与环境；无指标只能写静态风险。

与 API-004/ASYNC 重试叠加可导致调用放大；与 SEC 权限隔离相互核对。
