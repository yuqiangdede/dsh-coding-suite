# API：循环调用、重复请求、轮询和调用放大

## 调用链发现

从路由入口追踪 controller → service → repository/HTTP client/消息。前端从组件挂载、effect、轮询/定时器、状态依赖、拦截器、自动刷新追踪。服务间调用结合 OpenFeign/RestTemplate/WebClient/requests/httpx/axios/fetch、网关重写、服务发现、异步投递。静态分析给出候选图；链路追踪确认真实循环。

## 规则

| ID | 检查点 | 确认要素 |
| --- | --- | --- |
| API-001 | A→B→A 递归循环 | 全调用路径，终止条件与实际重复调用证据 |
| API-002 | 接口直接或间接无限递归 | 停止条件、最大深度、已见节点去重 |
| API-003 | 前端 effect/render 重复请求 | 依赖数组、状态写回、卸载后的轮询、路由多次订阅 |
| API-004 | 重复的相同读请求 | 相同语义/参数/授权上下文，请求内复用或共享缓存可行性 |
| API-005 | N+1 数据库或远程请求 | 迭代集合中逐条查询，对照批量查询方案 |
| API-006 | 多层重试倍增 | 网关/客户端/SDK/任务/队列的次数相乘；停止/退避/总时限 |
| API-007 | 无超时/无最大请求生命周期 | 各层 timeout 与 deadline 传递、取消机制 |
| API-008 | 无界或过密轮询 | 频率、停止条件、页面卸载清理、服务端推送替代 |
| API-009 | 缺并发限制/熔断 | 下游失败时上游继续加压，排队积压与线程占满 |
| API-010 | 错误的重复提交 | 超时后重试但后端缺 idempotency key/唯一约束 |
| API-011 | 大结果集/不合理分页 | 全量加载、无界 offset、序列化大对象 |
| API-012 | 缓存复用错误 | 数据强一致/权限相关而错误共享或跨租户缓存 |

## 报告格式

`入口 → 每跳具体方法/URL → 再入点 → 终止条件 → 是否有运行时复现 → 建议（批量/缓存/去重/中断）`。

示例：`页面 effect → GET /devices → 更新 effect 依赖 state → 再次 GET /devices`。示例不能作为项目真实证据。

避免误报：有界重试、正常分页、业务有意轮询和互相调用但不会在同一请求链回到起点，不属于无限循环。必须区分“静态潜在调用环”和“运行时确认死循环”。
