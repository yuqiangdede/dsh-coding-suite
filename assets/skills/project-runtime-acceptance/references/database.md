# DB：数据库表生命周期与清理闭环

## 清单覆盖（先完成）

交叉获取：迁移脚本/DDL（Flyway、Liquibase 等）、JPA/MyBatis/JDBC、SQLAlchemy/Django、手写 SQL、DB schema、外部数据库/分库分表/业务后台建立的表。包括临时表、历史分区、事件表、任务记录、软删除表、关联表。按 `实例/库/schema/表名` 归一，排除表要写依据。**数据库实际表清单优先用于校验代码盘点完整性**，不可访问时标记覆盖限制。

每张表记录：写入方、数据类型、预计日增量、数据分类、法定/业务保留政策、保留期限、执行机制（TTL、分区、归档、人工永久保留等）、清理入口、触发周期、过滤条件、关联资源、索引、证据与验证状态。`不需要清理` 必须有原因。

## 检查规则

| ID | 必查点 | 典型风险及确认方式 |
| --- | --- | --- |
| DB-001 | 表分类/保留策略缺失 | 高增长表无任何保留依据：需要代码+业务确认，不能单凭无 delete 断言 |
| DB-002 | 删除任务不存在/不可达 | 实际写入路径、任务注册、开关、条件、运行记录交叉验证 |
| DB-003 | 过期条件/时区错误 | 比较 UTC/本地时区、`<`/`<=`、状态过滤、时间字段含义及空值 |
| DB-004 | 软删除无限堆积 | 软删除记录是否有后续物理清理或归档策略 |
| DB-005 | 关联记录残留 | 外键、级联策略、业务关联和附件，跨 STORE 核对 |
| DB-006 | 清理与归档竞态 | 必须先确认可恢复归档完成，再清理源；检查并发任务锁 |
| DB-007 | 长事务/全表删除 | 批次大小、索引、锁争用、复制延迟、磁盘/redo、限速和失败续跑 |
| DB-008 | 分区/TTL 失效 | 分区预创建/裁剪、索引时间字段、DDL/策略版本与部署一致 |
| DB-009 | 清理失败无人感知 | 重试/告警、清理数量、最早过期记录时间、积压水位 |
| DB-010 | 异常历史记录滞留 | 失败任务、PROCESSING、幂等/重试记录是否永远保留 |
| DB-011 | 多库/租户覆盖遗漏 | 分库、分表、多个租户与临时 schema 的清理覆盖 |
| DB-012 | 清理后不可恢复 | 保留政策冲突、备份恢复不可用、误删防护、审计记录丢失 |

## 最小验证

- 静态核对：新增写入与清理查询谓词能否匹配（时间字段、状态、租户、分区）。
- 有只读环境权限时：表行数/占用趋势、最旧记录、超期记录量、最近成功清理时间和数量、关联残留；严禁因验收执行 DELETE。
- 如运行时不可访问，仅给出示例只读查询方案（明确数据库方言），不填写虚假结果。
- 验收结果按单表记录：`已核实策略 / 待核实 / 缺失策略 / 例外长期保存`，总数相加应等于在范围的表总数。

## 高风险关联

DB-005 → STORE 孤儿数据；DB-006 → JOB/CON 并发；DB-007 → PERF/RES；DB-009 → REC/SEC 告警。

## 禁止误判

基础字典表、依法长期保留的档案不需要定时删除；历史表可能通过按月 DROP PARTITION 清理；数据库 TTL、外部治理平台的清理规则不会出现在业务仓库里。
