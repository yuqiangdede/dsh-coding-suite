# SEC：安全、可观测性、日志和容量

## 安全规则

| ID | 规则 | 检查点 |
| --- | --- | --- |
| SEC-001 | 权限/租户隔离失效 | API 鉴权、业务对象权限、缓存键隔离、后台任务权限 |
| SEC-002 | 敏感信息泄漏 | 日志、配置、导出文件、异常堆栈、密钥；报告必须脱敏 |
| SEC-003 | 输入验证不足 | SQL 注入、路径遍历、不安全反序列化、任意文件读取 |
| SEC-004 | 外部开放接口无速率保护 | 暴力请求或重试耗尽资源 |
| SEC-005 | 过期/权限失效数据仍可取 | 缓存、临时 URL、对象存储 ACL、会话撤销 |

## 可观测与容量规则

| ID | 规则 | 检查点 |
| --- | --- | --- |
| OBS-001 | 关键任务无运行指标 | 成功率/耗时/数量/积压/最后成功时间 |
| OBS-002 | 数据增长无趋势监测 | DB 行数/容量、对象存储占用、日志容量/预测耗尽时间 |
| OBS-003 | 调用链缺关联 ID | 跨 API/异步事件无法定位重复请求与丢数据 |
| OBS-004 | 告警阈值无处置流程 | 谁处理、怎样定位、如何人工恢复，防告警疲劳 |
| OBS-005 | 日志永不清理/日志级别失控 | 日志轮转、保留周期、敏感数据脱敏 |
| OBS-006 | 容量预测缺前提 | 峰值 TPS、日增量、缓存内存与保留天数应来自测量或注明假设 |
| OBS-007 | 异常吞掉、告警缺失 | 捕获异常不记录上下文、任务失败不可见 |

可观测性不能替代业务正确性检查；“有监控”也不能直接宣称没有泄漏或不存在无限增长。安全发现若可能触发实际数据泄漏，报告只保留最小化、脱敏证据。
