# CON：并发、事务与数据一致性

## 规则

| ID | 检查点 | 推荐证据 |
| --- | --- | --- |
| CON-001 | 重复请求缺幂等保护 | 创建/支付/归档/通知等写接口有无唯一约束/幂等键 |
| CON-002 | 状态更新竞态 | 旧状态覆盖新状态、检查后再执行 TOCTOU |
| CON-003 | 事务边界不当 | DB/消息/外部 HTTP 在同一逻辑过程里提交不一致 |
| CON-004 | 锁范围/顺序错误 | 死锁、局部锁不能跨进程、不同锁序 |
| CON-005 | 乐观并发控制缺失 | version/CAS/状态谓词与受影响行数检查 |
| CON-006 | 隔离级别不足/过强 | 丢失更新、不可重复读、幻读与负载权衡 |
| CON-007 | 非线程安全共享状态 | 静态 Map、单例持有可变请求状态、共享连接 |
| CON-008 | 超时/取消后遗留副作用 | 客户端失败但后端已提交，重试重复操作 |
| CON-009 | 批处理与实时请求抢占状态 | JOB 归档/清理与业务写入相互干扰 |
| CON-010 | 数据复制/最终一致性无版本控制 | 延迟副本读取导致状态倒退 |

## 检查流程

识别共享资源、所有写入口、唯一约束与锁实现 → 建立状态迁移图 → 模拟同一业务对象的重复请求、并发请求、网络超时与重试 → 验证一致性与恢复。建议添加单元/集成并发测试，但默认不在生产执行压测。

缺少压测或 Trace 时，把竞态列为待验证，说明具体交错步骤，不能仅凭 `synchronized`/`Lock` 缺失报 P0。
